# Порты и брандмауэр

## Какие порты нужны

| Порт | Протокол | Кто использует | Если закрыт |
|---|---|---|---|
| 80 | TCP | выпуск и продление сертификата, переадресация на https | сертификат не выпустится и не продлится |
| 443 | TCP | сайт, API, чат | сайт не откроется |
| 3478 | UDP + TCP | голос: TURN/STUN | голос не заработает у части участников |
| 5349 | TCP | голос через TLS — запасной путь для строгих сетей (офис, некоторые провайдеры и мобильные операторы) | в строгих сетях голоса не будет |
| 40000–40100 | UDP + TCP | голос и демонстрация экрана напрямую к серверу | голос медленнее подключается или не работает |
| 50000–50100 | UDP | голос через relay (TURN) | голос не заработает у участников за строгим NAT |

SSH (обычно 22) тоже должен оставаться открытым — иначе вы сами не попадёте на сервер.

## Два брандмауэра

На сервере может быть **два** брандмауэра, и порты нужны в обоих:

1. **В панели хостинга** — называется Firewall, Security groups, «Сетевой экран», «Правила доступа». Есть не у всех. Открывайте **входящие** порты из таблицы выше. Hooba управлять им не может — только вы.
2. **На самом сервере** — UFW. Установщик предлагает включить его и открыть всё нужное сам.

## Если публичного IP нет на самом сервере

У некоторых хостингов (AWS, Oracle Cloud, Яндекс Облако и др.) на самом сервере только внутренний адрес, а публичный IP хостинг пересылает на него снаружи. Проверить можно так: `ip -4 addr` не показывает ваш публичный IP.

Делать ничего не нужно. `hooba install`, `hooba update` и `hooba repair` сами это замечают и пишут: «Сервер за NAT хостинга…». Запасной путь голоса (TURN) тогда работает на внутреннем адресе, а участникам по-прежнему сообщается публичный. Проверить настройки голоса: `hooba voice-check`.

## UFW вручную

Если отказались при установке или что-то сбилось:

```bash
ufw allow 22/tcp          # SSH — замените, если порт другой
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 3478
ufw allow 5349/tcp
ufw allow 40000:40100/udp
ufw allow 40000:40100/tcp
ufw allow 50000:50100/udp
ufw enable
```

::: danger Не закройте себе SSH
Если SSH на нестандартном порту — первой строкой откройте именно его. Иначе после `ufw enable` подключиться к серверу будет нельзя, останется только консоль в панели хостинга.
:::

Проверить, что открыто:

```bash
ufw status
```

## Проверить порты снаружи

С **другого** компьютера (не с сервера):

```bash
curl -I https://<адрес>
```

Ответ `HTTP/2 200` — сайт доступен. Голос проще всего проверить делом: зайдите в голосовой канал с двух устройств в разных сетях, например с компьютера и с телефона на мобильном интернете.
