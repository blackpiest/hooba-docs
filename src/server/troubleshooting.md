# Если что-то сломалось

## С чего начать

```bash
hooba status
```

Покажет, какие контейнеры работают, отвечает ли сервер, сколько осталось сертификату и места на диске. Во многих случаях достаточно:

```bash
hooba repair
```

Это пересоздаёт все контейнеры. **Данные не трогаются** — база, картинки и настройки остаются.

Если не помогло — смотрите журнал:

```bash
hooba logs backend    # сервер
hooba logs web        # сайт (nginx)
hooba logs coturn     # голос (TURN)
hooba logs postgres   # база
```

Выход из журнала — Ctrl+C.

## Сайт не открывается

| Что видно | Что проверить |
|---|---|
| Браузер долго грузит и пишет «время ожидания истекло» | Порт 443 закрыт в брандмауэре хостинга или сервер выключен. Проверьте панель хостинга и [порты](/server/ports) |
| «Подключение не защищено», сертификат истёк | [Продление сертификата](/server/certificates#сертификат-истек-или-скоро-истечет) |
| 502 Bad Gateway | Сайт работает, а сервер за ним — нет. `hooba status`, затем `hooba repair`. Если повторяется — `hooba logs backend` |
| Открывается чужой сайт или заглушка хостинга | A-запись домена указывает не на тот IP |

## Нет голоса или демонстрации экрана

Чат работает, а в голосовом канале не слышно друг друга или подключение висит.

Сначала запустите `hooba voice-check`: команда попросит зайти в голосовой канал, проверит, доходит ли голос до сервера, и подскажет, что делать. Отчёт для вопроса разработчикам она сохранит в `/opt/hooba/logs/voice-check-report.txt`. Если причина не нашлась, пройдите по списку:

1. **Порты.** Почти всегда причина — закрытые UDP-порты в брандмауэре хостинга: 3478, 40000–40100, 50000–50100. См. [Порты и брандмауэр](/server/ports).
2. **Контейнер голоса.** В `hooba status` должен работать `coturn`. Если нет — `hooba repair`, затем `hooba logs coturn`.
3. **Сервер установлен по домену до ноября 2026 года.** Браузерам мог передаваться домен вместо IP, и звука не было без единой ошибки. Выполните по очереди `hooba update` и `hooba repair`: одного обновления мало, адрес заменит только вторая команда.
4. **Сменился IP сервера** (например, после переезда). Запустите `hooba install` — он перепишет адрес для голоса.
5. **Не работает только у одного участника** — скорее всего, его сеть или браузер: пусть разрешит сайту доступ к микрофону и попробует другой браузер или мобильный интернет.

::: tip Демонстрация экрана на телефоне
Мобильные браузеры, как правило, не дают сайтам показывать экран: смотреть чужую демонстрацию с телефона можно, транслировать свою — с компьютера.
:::

## «Порт занят»

Во время установки: `Порт 80 занят программой …`.

- Если это `nginx`, `apache2`, `caddy` или `turnserver`, установленные в системе, скрипт сам предложит их остановить.
- Если `docker-proxy` — порт держит другой Docker-контейнер. Посмотрите `docker ps` и остановите лишний: `docker stop <имя>`.
- Иначе — остановите программу, которую назвал скрипт, и запустите установку снова.

## Не хватает памяти или места

- **Сборка падает** с `Killed`, `exit code 137` или `JavaScript heap out of memory` — не хватило памяти. Включите swap: запустите `hooba install` снова — на сервере меньше 2 ГБ он предложит создать swap-файл. Или возьмите тариф с 2 ГБ+.
- **`no space left on device`** — кончился диск. См. [Место под картинки](/server/storage#сколько-места-осталось-на-диске).

## Сервер не запускается: «placeholder value from an example file»

Такая строка в `hooba logs backend` значит, что в файле `.env.prod` остались пароли-заглушки из примера (`замените-на-…`, `change-me` и похожие). Эти примеры лежат в открытом доступе, поэтому с ними сервер не запускается: по ним любой мог бы войти как владелец. Установщик всегда пишет настоящие пароли — так бывает, только если файл собирали вручную.

В строке ошибки перечислено, какие значения заменить. Повторный `hooba install` не поможет: он сохраняет пароли, которые уже есть в файле.

1. На сервере получите новое случайное значение — для каждой строки своё:

   ```bash
   openssl rand -hex 32
   ```

2. Откройте файл и замените заглушки после знака `=` в строках `JWT_SECRET`, `SETUP_TOKEN`, `TURN_AUTH_SECRET` (только тех, что названы в ошибке). Сохранить — Ctrl+O, Enter, выйти — Ctrl+X:

   ```bash
   nano /opt/hooba/infra/docker/.env.prod
   ```

3. Пересоздайте контейнеры:

   ```bash
   hooba repair
   ```

После замены `JWT_SECRET` всем участникам придётся войти заново.

Если в ошибке назван `DATABASE_URL`, заглушка стоит в `POSTGRES_PASSWORD`. Пароль базы нужно сменить и в самой базе — иначе сервер к ней не подключится. Подставьте новое значение из `openssl rand -hex 32` вместо `<новый-пароль>`:

```bash
cd /opt/hooba && docker compose --env-file infra/docker/.env.prod -f infra/docker/docker-compose.prod.yml \
  exec postgres psql -U postgres -c "ALTER USER postgres PASSWORD '<новый-пароль>';"
```

Ответ `ALTER ROLE` — готово. Затем впишите тот же пароль в строку `POSTGRES_PASSWORD` в `.env.prod` и выполните `hooba repair`.

## Сервер не поднимается после перезагрузки VPS

Hooba запускается сам при старте системы. Если после перезагрузки сайт не открылся:

```bash
hooba start
```

## Ничего не помогло

1. Сделайте копию на всякий случай: `hooba backup`.
2. Попробуйте [откатить последнее обновление](/server/update#если-новая-версия-не-заработала), если проблема началась после него.
3. Соберите журналы для вопроса: файл `/opt/hooba/logs/<команда>.log` той команды, что упала, и вывод `hooba logs backend` за время ошибки.

::: danger Не публикуйте `.env.prod`
Отправляя журналы, проверьте, что в них нет содержимого `.env.prod` — там пароли сервера.
:::
